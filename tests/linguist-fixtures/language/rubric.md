# 语言验收判据（评价者使用，不注入被测任务）

这些案例为本方案作者独立创作，不取自客户稿。它们是小型回归与能力探针，不是完整语言质量金标或效能基准。可以增加真实新问题的脱敏等价例，但不要复制客户句子/术语/截图。

## 输入隔离

生成者只获得每例的 `id/stage/sourceLocale/targetLocale/source/currentTarget/brief/references`。`evaluation`、本文件以及参考答案不得进入被测请求、项目记忆或Skill。

每个岗位可一次读取一组案例并逐例输出，不要求每例独立模型调用。解释只需要必要修改的简短理由，不要输出隐藏思考过程。版本、模型、有效effort、资料和工具路径固定记录。

## 核对次序

1. 先看任务和Source，不先看作者名/理由，确定必须保持的含义与用途。
2. 查看目标文本是否准确、自然、适合角色与场景。
3. 检查实际要求、变量和格式。
4. 再看生成者的理由，判定其依据是否真实；不能用漂亮理由覆盖错误成果。

## 结果类别

- **通过**：完成该任务，语义与技术正确，语言达到场景用途；与参考表达不同不扣分。
- **需修改**：存在可定位的语义、语言、风格或任务要求问题；说明位置与影响。
- **正确保留**：既有表达合格且无需变化；E/P不因另有可选说法而改写。
- **正确待上下文**：案例确实缺关键运行/客户信息，保留已知事实并只提出必要问题；不能以此逃避其它可判断案例。
- **未验证**：缺真实模型输出、必要画面或合格评价依据，不能折算为通过。

## 质量维度

准确性：参与者、动作、对象、否定、时序、数量/边界、因果、限定与命名。
表达：自然搭配、信息组织、可读性、地区/受众与文本功能。
声音：语气、关系、节奏、隐含意图；不生造事实或口癖。
审校尺度：真正修好问题、保留合理变体；不以修改率为目标。
技术：稳定身份、正确变量/格式/换行，允许格式器支持的合法本地化变化。
依据：当前来源和适用性正确；没匹配不是不许专业判断；没独立批准不能假称批准。

## 发布解释

固定的关键机制/数据完整性案例若失败，修复相关根因再重验；平均风格分不能抵消错行或改数值。保留类案例被无收益改写也记录为方法问题。不同译法都合格时接受，不追唯一字符串。

模型自评只能辅助。对有争议的语义/创译及代表性保留项，进行一次盲核；不能声称同模型自评提供了独立人类验证。若无人工语言复核，报告明确“模型辅助评价”，不能包装成认证质量。

效率只在责任相同情况下比较。旧/新LA或原生Proma对照共享相同输入、资料和模型设置；Codex若工具/effort不等价就标非受控比较。记录准备与审校、TM/QA、提交、压缩/授权各自成本，不承诺倍数。
