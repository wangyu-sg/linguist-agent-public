# CAT Classify

This is a decision aid, not an output format. Normal CAT output still receives the target/candidate, not hidden reasoning or a classification essay.

## Two questions

1. **Function:** Is the text mainly informative/operational, expressive, persuasive, or approved-wording/mandatory?
2. **Distance:** Is it diegetic (inside the fiction) or non-diegetic (UI/meta around the game)?

Use the answers as a starting strategy, then obey typed project authority:

| Function | Typical content | Default move |
|---|---|---|
| Expressive, diegetic | Dialogue, narrative, lore, flavor, names | Recreate voice, subtext, tone, rhythm, and effect. |
| Informative, diegetic | Spoken tutorial, in-world stats/effects | Keep facts/terms exact while retaining speaker voice. |
| Operational, non-diegetic | UI, buttons, menus, errors, system text | Use terse, consistent target-market convention; no ornamental transcreation. |
| Informative, non-diegetic | Help, tutorials, quests, patch notes | Be clear, conventional, unambiguous, and structurally consistent. |
| Persuasive | Store, event, banner, marketing | Localize the selling effect while preserving offer facts and constraints. |
| Mandatory/approved wording | Legal, rating, trademark, platform-required text | Use supplied approved wording; otherwise raise a scoped query instead of inventing it. |

For mixed strings, keep the mechanical/informative part exact and localize only the expressive part. Genre tunes voice and density but never overrides typed project evidence. A style guide is one authority source, not a universal trump card.

## When to query

Query only when missing or conflicting context can materially change meaning, authority, compliance, or player action—for example unclear speaker/addressee, conflicting approved terms, absent mandatory platform wording, or a cultural adaptation that requires owner approval. Do not query routine linguistic choices that a senior localizer can responsibly make.
