# Terminology Candidate Mining

寻找真正需要统一决策的表达，不把所有高频词都升级成术语。

## 执行

1. **固定语料范围。** 用 `cat_list_assets` 确认批次，再用 `cat_get_segments` 分页读完用户指定的源文范围。若用户只要求抽样，先固定样本并在结果中声明；频次只能按实际已读范围计算。
   - 完成条件：已读 Segment 数、分页覆盖和未覆盖范围可核对，所有候选都来自该范围。
2. **生成候选。** 优先保留产品名、功能名、领域概念、专名、反复出现且会影响一致性的短语。合并不改变含义的大小写和词形变体；纯数字只要具有型号、版本、法规编号或其他项目决策价值，也可以成为候选。
   - 完成条件：每个候选至少附一个 Segment 证据和入选理由；通用虚词、乱码及无决策价值项已剔除。
3. **核对现有证据。** 对候选所在 Segment 分批调用 `cat_get_translation_context` 查看适用术语和冲突，再对 shortlist 逐项调用 `cat_search_terms` 判断“新增候选 / 已有一致 / 已有冲突”；需要参考历史译法时调用 `cat_search_tm`。不要把 substring 命中视为同一概念，也不要把搜索不到解释为批准。
   - 完成条件：每个候选都有术语查询结果；提出译法的候选另有 TM、Context 或明确标注的人工建议来源。
4. **排序并交付评审。** 按影响范围、实际频次和歧义风险排序，不生成伪精确分数；把无法裁决的差异写成问题。
   - 完成条件：候选状态、证据、建议译法、备选项和待确认问题均可逐项审阅。

## 输出

- **覆盖**：批次、Segment 数、分页/抽样方式和未覆盖范围。
- **新增候选 / 已有一致 / 已有冲突**：源术语、候选译法、实际频次、理由和 Segment/TM/术语证据。
- **待确认**：每项给出一个可回答的问题，不代替术语管理员裁决。

## 边界

- 不得调用 `cat_upsert_terms`、`cat_delete_terms` 或其他写入工具。
- 不把纯数字、大小写或风格差异默认升级为 hard rule。
- 搜索结果有上限；不能声称已穷尽全部术语或 TM。
- 不自动设置 `required`、`preferred`、`forbidden` 或 `deprecated`；状态由用户或授权评审确认。
