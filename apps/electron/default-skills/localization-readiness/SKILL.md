# 开工准备度检查

回答能否开工、哪些缺口真正影响当前范围，以及可以先做什么。不要把简单项目升级成固定验收流水线。

## 执行顺序

1. 复用本轮已知的项目身份、语言对和批次标识；不足时调用 `cat_project_summary`、分页 `cat_list_assets`。范围以用户要求为准；确实未限定时盘点全项目，并明确这一范围。
2. 尚未盘点或输入已变化时调用 `cat_refresh_project_inventory`。它会更新内部盘点记录，不修改译文，也不证明资料已经读过。本轮结果仍有效则复用。用户明确禁止任何项目状态写入时跳过，改用已有目录与只读信息，说明未刷新项。
3. 分开核对任务源批次、TM/TB、规则、Context、图片/其他媒体与映射。缺少文档 ID 时先在返回目录中找；不能只因不知道 ID 就向用户索取。未登记文件按已授权文件路径查阅，不擅自导入或把文件名当内容。
4. 用已有数量、状态和映射信息定位风险；需要看正文时读取相关句段。普通准备度检查可按批次、文本类型和风险取样，明确实际覆盖；用户要求全量时才读完完整范围。取样结果不能被表述为全量无问题。
5. 需要上下文或项目规则时调用 `cat_get_translation_context` 并设置 `readOnly=true`；按返回位置续读规则和必要参考，文档读取也设置 `readOnly=true`。需要时运行只读未知 Tag 扫描、术语冲突查询，不为开工盘点创建审校任务或确认句段。
6. 可通过现有资料解决的疑问先自行核验。源内容不可读、任务范围不能确定或结构无法保护，才列为关键阻断；可选参考不足、普通 warning 不自动阻断。锁定句段单独说明，不因此宣布其他可编辑句段不能开工。

## 结论与输出

先给一句结论，再给必要信息：

- `ready`：声明范围有可执行输入，没有已知关键阻断；列出仍需注意的非阻断风险。
- `needs-input`：部分内容依赖缺失事实或客户决定，明确受影响范围和可以先做的部分。
- `blocked`：当前目标整体缺少可执行输入或无法保护必要结构，明确原因与最小恢复动作。

只列影响译法、范围或交付的事项，每项附批次、Segment 或资料标识。没有阻断时直接说明可开工，不追加确认步骤。尚未全查的维度写未验证，不推断为已通过。

## 边界

本 Skill 默认只形成建议，不导入、不写译文、不改术语、不确认阶段、不导出，也不批准发布。用户明确要求“检查并导入/修复”时，在完成本检查后按该授权使用相应现有工具；不需要重复索取同一项授权。未获授权的外部发送、发布或范围排除仍不得执行。
