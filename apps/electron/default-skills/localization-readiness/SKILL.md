# 开工条件

先给能否开始的结论，只列影响真实任务的条件，不生成通用验收仪式。

复用当前语言对、用途、文件/批次和有效要求。缺身份时查已有目录/项目摘要；当前批次不等于全项目。尚未盘点或输入变化时，且用户允许内部记录，才刷新现有inventory。纯文件任务不必为盘点导入CAT。

分清源文件、TM/TB、规范、参考、媒体和映射。需要正文时按代表性风险取样，明确覆盖；只有用户要求全量时才检查整个指定范围。CAT读取用现有readOnly合同；不为盘点新建专业Stage或确认。

判断缺口影响：源文件不可读、范围未知、身份映射或必要结构不能保护，可能阻断相关工作；可选参考缺失、普通warning或部分锁定不自动阻断其它内容。新项目没有SG/TM时按现有任务和专业方法继续。

需要时查有效版本和资料原件，不以“文件存在”证明已理解。可解决的问题先自行处理，真正需要客户选择的冲突才列出。不要要求用户重新回答已有信息。

输出只需：可开工/可部分开工/当前阻断、实际检查范围、具体缺口与下一动作。不得声称未检查的语言/图片/运行效果已通过。默认不导入、不改译文或术语、不确认、不导出；明确的后续执行授权可以继续，不再重复请求。
