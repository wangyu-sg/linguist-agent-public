# 交付检查

先明确当前要判断的成果、范围和操作授权。已有有效检查不重跑；仅解释旧QA时不运行新QA。用户要求当前检查时，使用现有QA工具取得当前结果，明确其持久化副作用。严格无项目写入时只走只读路径。

对CAT成果使用现有项目/批次只读交付摘要；不为查询进度调用确认或准备导出。当前阶段、版本、候选、必要证据和QA分别查看。没有某种Agent Stage不自动否定合法的人工/文件成果；同时不得把旧confirmed当本轮独立审校。

检查实际有效规范与必要TEP责任是否已完成。规范只核了增量但无完整基线，不能宣称全覆盖；取了所有资料不等于逐段应用。需要新语言判断时针对相关内容，不靠术语检查或QA零提示推断整批语言无误。

按真实QA范围、finding身份和revision读取结果。真实问题在授权内修；误报以具体Source/Target、规则或批准来源判定，分类可复用但身份与适用性不丢。不为清零擅自忽略、解锁或改术语政策。修改后只刷新实际受影响的QA/规则范围。

只在有真实游戏、截图、音频或运行环境证据时报告对应LQA结论。没有证据的UI拼接、排版、配音和设备表现标未验证。跨批要求需取得实际跨批/平台joined证据，不能以单批结果代替。

输出实际已检查、重要问题、未决与可交付建议。ready仅限声明范围，不表示无限正确。导出/发送/平台完成依明确授权；verified失败不自动改as-is。只做报告不确认阶段，确认句段不等于交付工作。
