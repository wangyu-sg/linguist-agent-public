# 工作区定制版本的更新边界

仅在用户要更新项目 Skill、或新运行前发现已知流程冲突时使用本页。普通回填不先执行升级工作。

原生默认 Skill 同步按版本比较并整目录替换，不合并私有修改；停用的目录仍保持停用。工作区版本高于默认时，不会因新 App 已安装就自动采用新的默认正文。不要仅调高默认版本压过私有定制，也不要宣称默认文件更新证明实际请求已经加载。

在当前运行结束后的明确边界，按已有文件工具处理：

1. 确认该工作区实际 active/inactive 路径、当前正文与默认候选版本；备份原目录到该工作区私有备份位置。保持原启用状态。
2. 比较正文：保留项目身份、URL、稳定映射以及已经验证的输入/标签/保存方法，移入私有 reference；通用流程以当前模板为准，消除互相矛盾的追加。事故临时限制写明触发及解除条件，不把局部失败推广到所有行。
3. 将合并后的正文和私有 reference 写回原 Skill 目录，按实际工作区版本递增 patch。修改现有文件使用宿主原子写入能力；不要覆盖其它项目或把私有 reference 提交公开仓库。
4. 新运行通过原生加载核对实际来源、版本和正文。没有真实加载信息时，最多报告“文件已合并”，不能声称行为或性能已验证。后续正常任务只检查实际需要的结构类型，不为升级重跑完成批次。

权限或活动状态不允许更新时，保留当前文件并明确尚未迁移。默认模板更新和工作区私有迁移分别报告。
