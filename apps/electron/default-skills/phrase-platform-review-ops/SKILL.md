# Phrase 网页回填与 QA

先读 `in-app-browser`，复用当前授权 tab、稿件、映射和进度，仅补缺失或冲突的材料。

## 先确定最终差异，再连续执行

- 回填开始前按**工作 / 阶段 / 稳定句段 ID**收敛唯一清单：Source、当前 Target 底稿、最终 Target、必要的原生结构。PM 增量修订先在这份清单里解决；已有稿件不重新翻译。没有最终稿时先完成获授权的离线判断，不在网页上边找问题边改。
- **同一句的多个修改合并计划，只核验最终状态。**保留标签需要多个局部替换时，连续执行这些操作；不为每个词单独维护中间哈希，也不逆转后续修改来证明旧指纹。
- 已保存项直接续接进度；原已一致项零写入。未知保存、冲突或新改动只影响对应项，不触发整批重审。清单外语言疑点留给审校阶段，不扩大当前回填范围。
- 执行上下文只带任务链接、最终差异、进度和必要规则。换会话前先停止原会话写入，避免并发回填。

## 执行一次可靠的小组

1. **定位一次。**核对工作、语言对、阶段及授权范围。原始 key 与编辑器位置可能不同，以实际 paragraph/稳定 ID 和 Source 配对。AX 只有 Root 时转已观察的限定 DOM。
2. **复用方法。**一种结构已有身份、输入、读回及保存证据就连续使用。新遇到标签/特殊换行时才补一次校准。失败有具体新证据才试一种替代；仍失败就阻断该类型，继续独立可处理项，不拿客户行反复试验。
3. **写前紧邻检查。**在工具执行端检查工作、稳定身份、Source、当前 Target、原生结构与可编辑性。等于最终稿就跳过；等于底稿才写；其他值按冲突保留。组初预读不能替代写前检查。
4. **合并调用。**用 `BrowserAct.steps` 将定位、必要等待、guard、修改和最终读回组合在同一次调用。按 64 步 / 30 秒预算分组；正常项不在每个 click/fill 后返回模型重新决定下一步。普通输入字段用 `fill`；步骤以工具 schema 为准。
5. **保留原生结构。**普通无格式行可用已验证的整段输入；有 tag chip、格式或变量时采用保留结构的原生局部编辑。原生“替换全部”仅用于已经审定且匹配集合明确的小组，防止影响组外句段。按键用结构化 key，正文用 text；不把标签显示文本输入译文，不直接赋值 innerHTML/textContent，不上传文件或调用未授权写入 API。
6. **一次最终读回。**精确检查最终文本、标签身份/顺序/配对、变量、格式、真实换行与字面量 `\\n`；不 trim 或归一化文本。正常项无需另加 Observe、inspect、截图和离开重进。仅异常项追加针对性读取。
7. **组末保存与记账。**复用已验证、能归属于本次内容的保存屏障；没有可靠信号时，组末一次重载读回最终内容。DOM 变化、旧 Saved 图标、dispatched 或无关 2xx 不证明保存。统一更新同一清单的已保存、原已一致、冲突、未知和确认状态，正常输出只报数量与异常 ID，不反复输出完整正文和长交接。

## 使用固定 DOM 检查，避免重写校验脚本

当前工具 schema 支持时，`read/check/wait/guard` 优先使用：

```json
{"selector":"已观察的 CSS 选择器","attributes":["id","paragraph","data-tag-id","data-tag-content"]}
```

快照字段见 `in-app-browser`。直接比较最终期望值，不生成哈希；无匹配不算完成。逗号选择器可一次包含当前小组的句段身份、Source/Target、原生标签及锁状态。

以下 Phrase 结构已在历史现场见到，**仅在当前页面观察相符后复用**：`.twe_segment` 的 `id/paragraph`、`.twe_source`、`.twe_target`、`.te_tag` 的 `data-tag-id/data-tag-content`、`.lock_icon` 的 `aria-label`。textContent 可能包含标签编号和元数据，只用于比较，不是可输入译文。

搜索/替换框 `#filter-text-target` / `#replace-filter-input` 可用 fill。若切筛选复用旧行或出现 undefined ID，在同一组内**清筛选 → 等身份恢复 → 新筛选 → 等预期身份**，不能靠固定延时或重放修改消除漂移。

任意 `expression` probe 仍受 Chromium 副作用检查；遇到 `Possible side-effect` 改用固定 DOM 快照，不重复试同一脚本。复杂判断放在离线准备阶段，浏览器负责与确定结果比较。

## QA、TM 与确认范围

- 开始时明确回填、QA 运行/判读、TM 检查和确认各自范围。只确认现有译文不附加审校；仅检查编辑项不扩大为全批。平台只能全批 QA 时仍遵守用户的运行范围。
- 所需 TM 在确认前读取，须归属当前句段且刷新完成；空 TM 可记录，TB 不冒充 TM，确认产生的匹配不是独立证据。QA 只在再次修改使证据失效时复跑，不为清零批量忽略或对外发 Query。
- **仅明确要求才确认句段。**先查一次重复传播与自动锁定；保存未知、冲突、锁定或 QA 阻断项保留，明确可排除阻断时才处理其余范围。全部可处理且范围已核对时可原生批量确认，全选句段不是在输入框按 Meta+A。
- 完成/交付工作需另行明确授权；**用户要求保留 Accepted 时绝不完成/交付，也不点击确认通知中的完成链接。**不解锁、不新增锁定。意外传播计入实际影响范围并报告。

## 中断与收口

partial/unknown 返回后保留成功前缀，只读恢复受影响项并从未完成处续接。网站结构或保存信号失效就停止该方法。额外操作须对应具体未决事实；安全检查由执行端完成，不要求模型逐轮重做语言判断。

最终分别报告已回填保存、原已一致、QA/TM 范围与结果、未决项、确认数及工作状态。调用量和实际耗时可用于诊断；不把授权等待当编辑耗时，不承诺未实测的提速倍数。
