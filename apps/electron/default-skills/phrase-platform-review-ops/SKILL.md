# Phrase 网页回填与 QA

复用内置 `Browser*` 工具，按用户指定范围完成一批操作与记录。首次网页操作前读取 `in-app-browser` Skill，遵循其会话、ref 和登录流程；受管浏览器登录态按工作区保存在本机，不假定继承外部 Chrome 登录。

## 范围与权限

- 用户要求回填，即可在指定范围写入已审校译文；要求只读检查时不修改译文、不忽略 QA。平台编辑可能自动保存，写入前说明本次范围，已有授权不重复询问。
- 回填或 QA 不包含确认句段、完成任务、交付或解锁；这些操作须有用户明确授权。保留锁定及客户拥有的行。
- 开始时从用户当前要求确定回填、句段确认、QA 运行范围、QA 人工裁定范围及 TM 检查范围。用户要求优先于交接文档；“检查编辑项”不扩成全批重新审校。只要求确认现有译文时，不新增回填或 QA。
- 确认全部句段不等于完成工作。默认保持当前工作状态；用户要求保持“已接受”时，确认成功通知中的“将此工作标记为已完成”链接也在禁止范围内。
- 不使用 `Cmd/Ctrl+S` 保存 Phrase 任务，它可能保存网页。不要把自动保存、句段确认和任务完成混为同一状态。

## 执行效率

- 延续当前批次与已验证进度；已完成本地审校的批准译文直接用于回填，不重新逐句审校。已有稿件、映射和平台入口时直接进入编辑器，不把重新下载全量文件作为前置步骤；写前仍核对当前行，网页回填不转去探索上传入口。平台 Target 已等于批准 Target 的行核验后记为一致，不重复写入。
- 按当前页集中读取行身份、Source、Target 和编辑结构，生成本组差异清单。每种确有需要的编辑方式只做最小样本：文本、原生结构和保存结果验证成功即进入连续处理；不继续在成功行测试其他快捷键或选区方案。同类行复用已验证方式，按可见范围处理小组（例如 5–10 行），组大小服从页面虚拟化与保存能力。
- 普通纯文本行连续处理，标签、富文本、特殊换行和冲突行单独处理。集中读回仍须覆盖每个修改行，不用抽样代替核验。
- 优先替换实际变化的文字区间。原生标签次序不变时，不因文字大小写变化就整句删除、逐个重插标签；只有区间操作更复杂或原生结构确需重排时才重建，并核对标签身份与配对。不要把本批 key 偏移、变量名或一次性 DOM selector 写成通用规则。
- 正常行只需一次写前身份/旧值检查和一次写后读回，结果可合并在组内采集；已有结果覆盖的事实直接复用。额外检查必须针对具体未决疑点，不叠加 Observe、inspect、截图、离开重进来重复证明同一结果。已知点击后的等待条件时用 BrowserAct；读取限定区域，AX 只返回 RootWebArea 时改查已观察的 DOM，不反复扩大 Observe。不要逐字输入、每行输出长分析或固定等待；任务清单按阶段记录，逐行进度只进入同一份清单。
- 同一标签上的写入保持串行。遵循 in-app-browser 的 ref 失效规则，不跨重渲染复用旧 ref。工具没有多动作参数时不要虚构批处理接口；若固定工具确实无法表达所需的多行批处理，才按浏览器 Skill 使用基于已观察结构的最小 BrowserExecuteJavaScript。先验证单行的编辑事件、平台保存和读回，再扩展到小组；脚本逐行校验身份与旧值、等待编辑器接受修改，并返回逐行结果。直接改变 DOM 外观不算平台写入。
- 使用单一按 Segment ID 索引的进度清单，每组持久化已写入且读回、原已一致、传播后一致、待核验、冲突和恢复事件；不要让多个可变 pending 数组分别充当进度真源。中断后只读回未定项。记录组起止时间与工具调用次数；等待用户授权单列，不计作编辑、保存耗时或超时故障。无逐调用时间证据时不推算工具耗时，不承诺提速倍数。

## 回填

1. 复用已提供的任务 URL、语言对、批次及审校结果；读取必要的术语、Style Guide 和项目证据。用 `BrowserListTabs` 复用标签，核对页面可见的任务身份。缺少明确的目标任务或批准译文时，先补齐信息再写入。
2. 建立待改行清单：平台 Segment ID／行号、Source、原 Target、批准 Target。逐行核对页面 Source 和当前 Target；不只凭屏幕位置或本地行号匹配。遇到重复 Source 无法区分、行映射不明或平台译文已变化时，暂停该行并记录冲突，不覆盖新内容。
3. 使用最新 `BrowserObserve`／`BrowserFind` 的 ref。普通纯文本字段可用 `BrowserFill`；含原生标签或富文本时先检查结构，通过点击、定位光标和编辑器原生操作修改文字。整段 Fill 会替换内容，不用于保留标签或格式。无可用 ref 时按浏览器 Skill 使用 `BrowserDomAction`；不硬编码未观察到的 selector。
   - 无标签、无富文本的自绘目标字段若不能 Fill，可复用已验证的“原生删除译文按钮 → 聚焦目标输入框 → BrowserPress 整段文本 → 读回”路径；删除前保留旧值，不能把此路径用于保留原生结构的行。无需为纯文本替换反复试验全选组合键。
   - Phrase 自绘编辑器的目标 cell 不等于已激活输入框。点击文字区后，核对实际输入框所属 Segment ID 和 Source，再向该输入框发送编辑动作。点击可能只滚动到目标或选中 tag；不要向未核对的全局活动输入框发组合键。
   - 筛选可用于定位；为避免编辑后筛选重渲染丢失身份，定位后清除筛选并重新绑定目标，再写入。未渲染行不等于不存在；行身份为空、变化或错位时停止该行，读回受影响内容后恢复定位。
4. 原生 tag chip 必须仍是 chip，不能用看起来相同的字符串代替。保留占位符、标签顺序与配对、下划线及其他格式。需要插入标签时先核对当前编辑器菜单／快捷键提示，再用原生插入操作；不能可靠插入或读回时停止该行，不反复盲写。
   - 当前 BrowserPress 将导航键白名单以外的字符串作为文本插入；`Meta+A`、`Control+A`、`F8`、`Shift+Enter` 都不能直接作为快捷键名称传入。标签优先用原生“插入标记”按钮；组合键所需操作按当前工具文档选择原生菜单或必要的最小页面脚本，只验证确实需要的方式。`dispatchEvent` 返回或 `defaultPrevented` 不证明选区/编辑成功，以实际选中内容和读回为准。
5. 换行按当前项目规则处理；不默认把字面量 `\n` 转成换行。若项目明确要求源硬换行和字面量 `\n` 分别对应目标硬换行，则相邻两者需保留两个硬换行。通过当前编辑器支持的操作插入并核验，不用空格代替。
6. 每组修改后集中读回所有修改行的 Target，核对文本、占位符、换行、标点、前后空格、截断及可见保存状态。普通行已有可靠保存结果时，不机械地逐行离开再回来；保存状态不明、异常或结构复杂的行再重新定位，必要时截图核验标签与富文本。组末等待当前修改保存完成再切页。工具中断时先读回，确认是否已写入再决定是否重试；未核验行记为未完成。

## TM、确认与异步结果

- 需要 TM 检查时，选择句段后等待匹配面板对当前选择完成刷新，记录选择身份、读取阶段及实际匹配。面板非空或第一条仍存在不是刷新证据；模糊匹配原文本来可能不同，须结合选择上下文与刷新状态判断。只有 TB 结果时记录“仅 TB”，不写成 TM 已通过。
- 在该范围确认前保存所需 TM 证据；确认可能把本次译文写入 TM。确认后补读须标注，不能把后来出现的 100/101 分当成独立验证；面板归属未核实则记为未解决。
- 获授权确认时，在相应范围回填、必要检查和保存完成后单独确认，避免逐条确认自动跳转与下一条编辑争焦点。用户要求全批确认且全部可处理时，可清除筛选、核对全选范围并使用原生批量句段确认；用当前阶段统计验证结果，保留工作状态。
- 浏览器等待用户授权时保持等待，不重复索权或诊断成工具超时。实际写入或确认调用报超时时记录“结果未知”，不重复提交；用有界只读查询等待业务状态，连续无新证据的超时后保存进度并报告阻断。

## Phrase QA

1. 用户要求平台 QA 时，按指定范围执行；未限定运行范围时可运行全批一次。只要求检查编辑项时，裁定范围为实际编辑集合；全批 QA 的其他提示另列，不把它们加入本次逐条处理。仅要求解读现有 QA 时不重跑，并注明结果时间及新鲜度未知。LA 本地 QA 不能代替 Phrase QA。
2. 核对 QA 运行范围，逐页加载需要处理的全部结果，记录数量与加载结束证据。每次加载后等待结果条目增加或明确加载结束；瞬时按钮消失、未变化的旧列表都不是完成证据。没有新结果时不连续点“加载更多”。按问题自身的 Segment ID 关联，不能沿用表格合并单元格、显示序号或上一行编号。最后一个 QA 问题的行号不代表最后一个受检 Segment。
3. 范围内每个非确认问题结合 Source、Target 和项目依据判断。同一规则可以复用证据，但必须验证每条适用并关联依据，不能批量套“语义已覆盖”当作术语批准。术语结合完整复合词和客户已确认用法，格式检查同时看原生标签、可见效果与换行规则；不能为清零而批量忽略。
4. 获授权修复时修正真实问题，重跑 QA 并核实消失。仅在本次授权包含 QA 忽略操作时，将已验证误报标记忽略并记录依据；否则只列出建议。未确认句段警告保留，不为消除警告而确认句段。
5. 每项区分判读结论与平台动作：已修复且复跑通过、已忽略误报、保留已核实误报、保留真实问题、保留未确认警告、范围外或未解决。仅保存匹配文本、填写分类或留下通用理由不算依据核实；未确认的专名/术语候选保留为未解决。只有新增实际修复或结果失效才复跑 QA。

## 批次记录与完成标准

使用当前工作区内的 Markdown 报告记录任务 URL、运行时间、范围、待改／已改且读回／跳过／阻断行数，以及 QA 初跑总数、非确认问题数、各处理类别数量和复跑剩余数。初跑与复跑分别计数，避免把同一问题重复累计。

对每个回填行和非确认 QA 项保留 Segment ID、Source、修改前后 Target、问题、动作、依据及验证结果。区分原平台已有问题与本轮回填引入的问题；无证据时写来源未确定。

分别报告回填、句段确认、QA 覆盖与裁定、TM 证据的完成状态；未要求的阶段标记不适用。回填完成不等于质量全通过。未解决项给出行号与证据缺口；缺少读取范围或筛选证据时，QA 数量只称“当前已读取条目数”。报告直接写入、原已一致/传播后一致、恢复事件各自数量，不能把工具调用成功当作平台验收或任务已交付。
