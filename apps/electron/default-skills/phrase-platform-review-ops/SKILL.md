# Phrase 网页回填与 QA

复用内置 `Browser*` 工具，一批完成回填、平台 QA 和记录后再处理下一批。首次网页操作前读取 `in-app-browser` Skill，遵循其会话、ref 和登录流程；受管浏览器登录态按工作区保存在本机，不假定继承外部 Chrome 登录。

## 范围与权限

- 用户要求回填，即可在指定范围写入已审校译文；要求只读检查时不修改译文、不忽略 QA。平台编辑可能自动保存，写入前说明本次范围，已有授权不重复询问。
- 回填或 QA 不包含确认句段、完成任务、交付或解锁；这些操作须有用户明确授权。保留锁定及客户拥有的行。
- 不使用 `Cmd/Ctrl+S` 保存 Phrase 任务，它可能保存网页。不要把自动保存、句段确认和任务完成混为同一状态。

## 回填

1. 复用已提供的任务 URL、语言对、批次及审校结果；读取必要的术语、Style Guide 和项目证据。用 `BrowserListTabs` 复用标签，核对页面可见的任务身份。缺少明确的目标任务或批准译文时，先补齐信息再写入。
2. 建立待改行清单：平台 Segment ID／行号、Source、原 Target、批准 Target。逐行核对页面 Source 和当前 Target；不只凭屏幕位置或本地行号匹配。遇到重复 Source 无法区分、行映射不明或平台译文已变化时，暂停该行并记录冲突，不覆盖新内容。
3. 使用最新 `BrowserObserve`／`BrowserFind` 的 ref。普通纯文本字段可用 `BrowserFill`；含原生标签或富文本时先检查结构，通过点击、定位光标和编辑器原生操作修改文字。整段 Fill 会替换内容，不用于保留标签或格式。无可用 ref 时按浏览器 Skill 使用 `BrowserDomAction`；不硬编码未观察到的 selector。
4. 原生 tag chip 必须仍是 chip，不能用看起来相同的字符串代替。保留占位符、标签顺序与配对、下划线及其他格式。需要插入标签时先核对当前编辑器菜单／快捷键提示，再用原生插入操作；不能可靠插入或读回时停止该行，不反复盲写。
5. 换行按当前项目规则处理；不默认把字面量 `\n` 转成换行。若项目明确要求源硬换行和字面量 `\n` 分别对应目标硬换行，则相邻两者需保留两个硬换行。通过当前编辑器支持的操作插入并核验，不用空格代替。
6. 每行修改后读回 Target，并按需截图检查标签、富文本、占位符、换行、标点、前后空格和截断；离开并重新定位该行，检查内容保留及可见保存状态。状态不明或工具中断时先重新观察，确认是否已经写入，再决定后续动作。未核验的行记为未完成。

## Phrase QA

1. 回填后默认运行该批次完整平台 QA；用户明确限制范围时遵循其范围。仅要求解读现有 QA 时不重跑，并注明结果时间及新鲜度未知。LA 本地 QA 不能代替 Phrase QA。
2. 核对 QA 检查范围覆盖整批，逐页展开／加载全部结果，记录总数与加载结束证据。不能以“最后一个 QA 问题的行号”证明覆盖最后一个 Segment；无报错的行也在检查范围内。结果加载不全时明确标记覆盖未完成。
3. 每个非确认类问题都结合 Source、Target 和项目依据逐段判断。术语结合完整复合词和客户已确认用法，格式检查同时看原生标签、可见效果与换行规则；不能为清零而批量忽略。
4. 获授权修复时修正真实问题，重跑 QA 并核实消失。仅在本次授权包含 QA 忽略操作时，将已验证误报标记忽略并记录依据；否则只列出建议。未确认句段警告保留，不为消除警告而确认句段。
5. 每项记录为：已修复且复跑通过、已忽略误报、保留真实问题、保留未确认警告或未解决。未执行的建议忽略、缺少依据及工具阻断均写明原因，不计作已处理成功。

## 批次记录与完成标准

使用当前工作区内的 Markdown 报告记录任务 URL、运行时间、范围、待改／已改且读回／跳过／阻断行数，以及 QA 初跑总数、非确认问题数、各处理类别数量和复跑剩余数。初跑与复跑分别计数，避免把同一问题重复累计。

对每个回填行和非确认 QA 项保留 Segment ID、Source、修改前后 Target、问题、动作、依据及验证结果。区分原平台已有问题与本轮回填引入的问题；无证据时写来源未确定。

只有指定行全部读回通过、QA 覆盖完整且每个非确认问题有结论时，才报告本次流程完成；保留问题仍须列出。任何未解决项都明确给出行号和阻断，不把工具调用成功当作平台验收或任务已交付。
