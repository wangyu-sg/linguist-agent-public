# Phrase 网页回填与 QA

使用当前会话的内置 Browser 工具。首次操作先读取 `in-app-browser`，复用已授权工作 tab 和已有登录流程；等待用户授权单独计时。不要使用外部浏览器、文件上传或未授权的直接写入 API 替代用户指定的网页编辑器操作。

## 任务边界

复用已批准译文、原 Source、原 Target 和稳定句段映射，不重新翻译。分别确定回填范围、QA 运行范围、QA 判读范围、TM 检查范围和句段确认范围；只确认现有译文的任务，不附加回填或全批审校。

网页修改可能自动保存。已有范围授权不逐行重问。句段确认不等于完成工作：除非用户另有明确指令，不操作完成/交付入口；用户要求保留“已接受”时，始终保持 Accepted 和原有可编辑性，不点击确认通知中的完成工作链接，不解锁客户行、不新增锁定、不批量忽略 QA、不对外发送 Query。

## 执行流程

1. **复用材料和进度。**使用现有任务 URL、语言对、流程阶段、原稿、批准稿、映射及唯一进度清单。只有缺失、冲突或用户要求备份才补读或下载；不探索上传入口，不固定重读整套术语和 Style Guide。报告条数不等于实际应写次数。
2. **定位实际编辑器。**先列举并复用工作 tab，核对工作、语言对、当前流程阶段及范围。外层页面无正文或 AX 只有 Root 且加载状态没有变化时，确认 tab/frame 后转已观察结构的限定 DOM 读取，不连续重复全页 Observe/Extract。未渲染行不等于不存在；不得按可见行序号或固定偏移映射句段。
3. **一种结构只校准一种方法。**证明句段身份、实际输入节点、正确读回和本次保存依据后，立即连续使用。纯文本成功后不再测试其他全选/选区方案；标签、富文本和特殊换行在实际遇到时再校准。失败只在有新证据时验证一种替代方案；仍不可靠就记录该类型阻断，继续其他可独立处理的类型。不反复改动真实客户句段做试验。
4. **每次写前即时比对。**在执行端紧邻写入核对工作与句段身份、Source、当前 Target、原生结构和可编辑性。当前值及结构等于批准结果则零写入跳过；等于底稿才修改；两者都不等、映射有歧义或焦点不属于该句段就不写。组初预读不代替中间已发生变化后的写前检查。不任意 trim、折叠空白、归一化横线或合并真实换行与字面量 `\n`。
5. **选择最低可靠成本的方法。**无标签、无富文本的行，可复用已验证的原生删除译文加整段输入，或已验证的局部修改；不为只改一个字符强求复杂选区。含原生结构的行只通过保留结构的编辑方式修改文字；不将 tag chip 改为普通字符串，不用 innerHTML/textContent 赋值伪造修改。标签身份、顺序、配对、变量、格式及真实换行均需正确。
6. **按真实工具契约操作。**以当前暴露的 schema 为准。支持结构化 BrowserPress 时，按键使用 `action.kind="key"`，正文使用 `action.kind="text"`；不要把 `Meta+A` 等字符串当正文参数执行快捷键。旧版工具不支持组合键时，使用已验证的原生按钮/菜单，不猜接口。输入绑定实际编辑节点；选区建立后只校验焦点，不重复 focus 清掉选区。
7. **有界串行处理。**支持 BrowserAct 的 steps 变体时，用一次调用完成一行或一个已校准小组的定位、检查、输入、等待、读回。预读的一致项和冲突项不进入写入序列；同一 tab 不并行写。从一行开始，稳定后按实际保存速度和工具预算组成小组，不硬凑固定行数。稳定 ID/Source 筛选可以保留；只有编辑会改变筛选成员时才调整。重渲染后重新解析定位规则，不复用旧 ref。没有 steps 时不虚构批量能力，也不把长时间写入循环塞进页面 JavaScript。
8. **读回一次，验证本次保存。**每个修改项核对文本、原生标签/格式、变量与换行，并获得可归属于该次内容的保存依据；允许逐行读回、组末用已校准的保存屏障完成验证。旧 Saved 图标、DOM 已变化、工具 dispatched 或无关 2xx 都不能单独证明保存。正常项不再固定离开重进；未知、失败或中断只读恢复受影响项，不盲目重写、Undo 或重放成功前缀。
9. **按授权范围检查 TM/QA。**需要 TM 时，在确认前读取归属当前句段且已刷新完成的匹配；空 TM 是可记录结果，TB 不冒充 TM，确认后产生的 100/101% 匹配不作为独立证据。只检查实际编辑项时，不把其他 QA 提示扩成新审校任务。QA 运行范围与判读范围分别记录；平台只能全批扫描时仍遵守用户对运行范围的明确限制。真实再次修改导致结果失效才复跑。未授权忽略就只报告误报判断；不为清零批量忽略或发送 Query。
10. **确认与回填分开。**开始时检查一次重复传播及自动锁定行为；不得让确认覆盖已知冲突或暗中扩张修改范围。回填、所需检查和保存明确后，使用原生句段确认。全部可处理时核对工作、阶段及全选范围后批量确认；有冲突、未知保存、锁定或 QA 阻断时，保留未决项，只处理可明确排除阻断的范围。全选句段不是向编辑框发送 Meta+A。不要为凑满确认数关闭 QA、解锁或点击完成工作。
11. **分组记账与结束。**每组更新同一份按工作/阶段/句段 ID 索引的记录：已写且保存、原已一致、已核验传播影响、冲突、未知/阻断及确认状态，附必要 QA/TM 依据。意外传播的行也计入实际影响集合。最后分别报告回填、检查、当前阶段确认数、工作状态与可编辑性；不得将这些合并成笼统的“全部完成”。

## 结果与异常

写前冲突、写后不一致、保存未知、TM 未刷新是不同问题。额外操作必须对应具体未决事实；已有证据足够就复用，不叠加 Observe、inspect、截图和离开重进证明同一结果。只有图像/布局/原生结构确需视觉辨识时才截图。

浏览器首次风险确认、登录和其他用户授权沿原生流程等待，不重复索权、不记作编辑超时。时间线区分准备/校准/回填/检查/确认，以及模型往返、工具排队执行、保存等待和授权等待；没有逐调用数据不推断耗时根因或承诺提速倍数。

工具中断返回 partial/unknown 时，成功前缀不重放；只读核对最后一组未定项，再从未完成项继续。网站变更或保存信号失效时停止受影响方法，不以更多盲操作补救。
