# 文化与语用检查

根据实际语境作专业判断，不把个人偏好、文化刻板印象或模型记忆当成普遍事实。

## 执行顺序

1. 从用户和项目资料确定目标地区、受众、渠道、人物关系与任务范围。先用已有上下文补齐，不要求用户重填已知信息。只有缺失信息会实质改变判断时才澄清；可完成的其他检查继续。
2. 对指定范围取得 Source、完整 Target、邻接文本和项目规则。纯报告时 `cat_get_translation_context` 使用 `readOnly=true`，读取相关 Context 也使用 `readOnly=true`；必要规则与参考继续分页，不凭摘要决定图文或人物动作。
3. 已知 speaker 时复用批量 Voice 信息，必要时调用 `cat_get_voice_context`。项目中的批准用法优先；不能从一个名字、地区或口音猜测人物敏感属性、政治立场或客户意图。
4. 检查称谓关系、礼貌程度、幽默典故、日期单位、表达强度和图文配合。区分明确错误、依赖场景的风险，以及需要外部事实的疑问。普通有上下文的语用问题可以直接给出有依据的修改建议，不机械转交母语者或专家。
5. 涉及现实地区习惯、当前用法或合规事实且内部资料不足时，使用已有搜索/浏览器能力核验可靠来源。无法核实时标记不确定性；只有客户立场、授权决定或真正的法律合规判断才升级给相应负责人。
6. 默认给报告。用户明确要求修复时，在授权范围内使用已有写回工具；用户要求先看建议则保留 Proposal。不能借文化适配擅自改变立场、删情节、强化人物口吻或抹去有意的风格差异。

## 输出

按“确认问题 / 情境风险 / 待外部核验”组织，仅列实际存在的类别。每项提供位置、决定判断的上下文、影响和最小修改方向；可接受的变体说明适用条件，不伪精确打分。

无问题时报告实际覆盖范围即可，不制造风险凑数。缺少图像、地区事实或客户决定时写清具体缺口，不以泛泛的“建议找专家”代替已经能完成的分析。

## 边界

不自动修改术语政策、确认阶段、waive QA 或批准发布。自动 QA 不能证明文化适配；图片标题不能证明视觉内容；一般语言经验可以支撑专业建议，但不能冒充经外部来源验证的事实。
