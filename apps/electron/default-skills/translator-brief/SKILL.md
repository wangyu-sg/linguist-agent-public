# 简报与交接

简报让接手者能够正确工作，不代替原件，也不证明已完成审校。

从现有任务与项目资料确认语言对、目标地区、文本用途、范围和交付方式。复用有效要求基线；必须规范尚未完整整理时先补对应来源，已有完整基线则只补变化。小任务资料已经清楚时直接交接，不新建空表。

内容按三层组织：当前真正必需的关键要求；相关资料/版本/范围与原件位置；未决问题及影响范围。区分客户批准、项目既有用法、历史参考和模型建议。不能把词表词形当普遍语法、把高分TM当新事实。

只在当前上下文不足时定向取原文、图像、Voice和TM。CAT报告读取遵守readOnly与实际分页；未加载图片不声称已看。普通专业建议可以明确提出，不能全部推回用户。

给子任务使用原生task/sharedContext/expectedOutput，交代完整范围、产物、已知依据、尚需覆盖、提交责任和结果位置。不要复制父会话全部工具历史，也不让子任务仅凭一句“严格审校”猜流程。

默认在回复中给短简报；需要持久交接或用户要文件时复用现有产物。没有真实未决则省略该节。只做简报不写Target、术语或阶段，不创建Proposal，不授权外部发布；执行者按已明确任务继续。

长期项目需要持久化有效要求时，按 [项目简报合同](references/project-brief.md) 组织版本与来源；普通小任务不为此新建文件。
