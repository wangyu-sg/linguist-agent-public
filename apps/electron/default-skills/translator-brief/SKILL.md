# 译者简报

只保留会改变译法或交付结果的信息，使接手者知道翻什么、按什么要求翻，以及哪些事实仍未确定。

## 执行顺序

1. 从当前上下文确认语言对、目标地区、批次和文本用途；缺少时用项目概览与批次目录读取。文本类型可用有说明的代表性样本判断，不把样本冒充整份语料。
2. 从已有 inventory、Digest 或授权文件目录定位规则与 Context；尚未盘点且任务允许内部记录时刷新一次 inventory。没有现成文档 ID 先查目录，不猜造资料内容，也不立即把检索工作交回用户。
3. 对相关句段调用 `cat_get_translation_context`，设置 `readOnly=true`。普通页提供部分规则；`ruleCoverage.remaining` 大于零时，使用同一组 `segmentIds`，设置 `rulesOnly=true`、`rulesOffset=ruleCoverage.nextOffset`、`readOnly=true` 继续读取。不要把 Digest 或规则第一页当全集。
4. 对决定译法的 Context 继续用 `cat_read_context_doc(readOnly=true)` 读取正文或图片，并跟随实际下一位置。已知 speaker 且批量上下文不足时，用 `cat_get_voice_context` 核对 Voice 和批准译例。读取图片目录不等于看到图片。
5. 复用批量上下文已有的术语、TM 与来源。仅对尚未解决的命名、变体和冲突补充 `cat_search_terms`、`cat_search_tm`；高匹配译文不自动成为客户规则。冲突先核对版本、适用范围和批准状态，可确定时自行说明依据，无法确定时才保留待确认项。
6. 合并重复要求，不复制整份资料。允许提出有依据的“模型建议/暂定约定”，但不得伪装成客户批准或人工审定；不要为了回避判断把所有专业建议都改成用户问题。

## 输出结构

### 任务与范围
语言对、目标地区/用途、纳入批次、实际取样或阅读范围；未知项写未提供。

### 必须遵守
仅列有明确项目依据的术语、命名、格式与风格要求，每项附来源标识和适用范围。

### 参考与译法建议
相关 Voice、批准译例、TM 参考及必要的正反例。模型新提议显式标为建议；项目无依据时不要指定固定体育译名、角色口癖或宣传风格。

### 尚待解决
只列会改变译法或交付结果的缺口、冲突双方、已核验内容及可继续部分。无待确认项就省略，不为了凑模板制造问题。

## 边界

默认在回复中给出简报；用户要求文件或指定位置时再创建文件。不写译文、不写术语、不确认阶段、不自动导出。简报是导航与决策摘要，不能替代原始规则，也不能证明全量审校完成。
