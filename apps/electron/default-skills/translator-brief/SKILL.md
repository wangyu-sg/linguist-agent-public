# Translator Brief

只保留会改变译法或交付结果的信息，并让每条要求可追溯。

## 执行

1. **固定任务范围。** 用 `cat_project_summary` 读取语言对，用 `cat_list_assets` 分页确认批次。需要判断文本类型或角色时，用 `cat_get_segments` 读取用户指定范围；大范围只做有说明的代表性取样，不伪装成全量阅读。
   - 完成条件：简报明确列出纳入、排除和抽样范围，并报告分页或样本覆盖。
2. **收集项目证据。** 对选定 Segment 分批调用 `cat_get_translation_context`，首批启用项目规则并保留 Segment、术语和 TM evidence id。用 `cat_list_term_conflicts` 暴露冲突；只对简报中的关键短语调用 `cat_search_terms` 和 `cat_search_tm`。已知 speaker 时再调用 `cat_get_voice_context`；已知 Context 文档标识且内容相关时分页调用 `cat_read_context_doc`。没有标识就报告缺口，不猜资料内容。
   - 完成条件：每条“必须遵守”都有项目规则、术语、批准译例、Context 或 Segment 证据；无来源内容不得进入该栏。
3. **压缩为执行口径。** 合并重复规则，保留冲突而不是替用户裁决；把风格、称谓、禁用项、结构保护和参考译法分别归入“必须遵守”“参考优先”“待确认”。
   - 完成条件：同一规则只出现一次；冲突双方及来源同时保留；所有推测均已删除或转为问题。
4. **检查可用性。** 从一个未读过项目的人视角检查简报，确保他能知道翻什么、为谁翻、必须保护什么以及遇到冲突问什么。
   - 完成条件：任务目标、范围、关键规则、证据和待确认问题五项齐全；缺一项就明确写“未提供”。

## 输出

- **任务目标与范围**：语言对、批次、受众/用途及覆盖说明。
- **必须遵守**：规则、术语和结构要求，每项附证据标识。
- **参考优先**：Voice、TM、译例与 Context，标明适用条件。
- **待确认**：冲突或缺失事实，一项一个问题。

## 边界

- 不复制整份项目资料，不把模型常识写成客户规则。
- 不调用翻译写回、术语写入、阶段确认或导出工具。
- 搜索结果和项目规则都有条数上限；不得声称已穷尽全部 TM、术语、Voice 或 Style Guide。
- 简报不能替代原始 Style Guide、术语库或批准译例。
