# Agent Context

Product version: `2.32.7`.

## Current product

Linguist Agent is one local macOS product: Electron in `apps/desktop`, an authenticated loopback `cat-server`, Pi-native Agent runtime adapters, a General Core, and a game-localization Expert Layer. SwiftUI and browser clients are deleted and must not reappear as compatibility layers.

A canonical Task owner is either standalone or Project. Both use Task / Run / Agent thread / Activity / Artifact / Decision. Standalone is the ordinary no-project Chat. Project Tasks may add Batch, locale, Segment, evidence, CAT, Team, Eval, QA, and Delivery scope. There is no runnable Home Agent; legacy Home records migrate into one archived standalone Chat.

## Source owners

- `packages/cat-data`: durable standalone/Project truth, file grants, Library, confirmed memory, document capability/qualification state, evidence, workflow, Eval, QA, and delivery.
- `packages/cat-runtime`: General/CAT/Maintainer Pi session construction, pre-execution resource snapshots, permissions, sandbox, compaction, delegation, and request shapes.
- `packages/cat-tools`: general document/Library/memory tools and CAT-facing tools/gates.
- `packages/cat-server`: authenticated APIs, active-run ownership, Task projections, resource trust, Package Center, Maintainer, Settings, and runtime lifecycle.
- `apps/desktop`: the maintained client and macOS release surface.
- `contracts/schemas` and sanitized fixtures: client/server wire compatibility.

Do not infer state from prose when code, tests, runtime output, or a manifest can answer it. Do not infer that `/Applications/LinguistAgent.app` or the Application Support runtime matches this checkout.

## Runtime facts that matter

- Standalone transport is `/api/tasks/*`; Project Task transport remains `/api/projects/:projectId/tasks/:taskId/*`. Server-derived Pi identity and the canonical active-run registry own execution.
- Runtime schema v2 makes Task ownership explicit. Standalone scope cannot contain Project/Batch/Segment fields, and Project/standalone storage roots cannot collide.
- General startup first compiles a JSON-serializable schema-v1 `GeneralAgentSessionPlan` before any Pi Session exists. The Plan freezes the resolved workspace/grants, permission contract, model inputs, prompt inputs, resource snapshot, and exact initial/registered tool surfaces behind content hashes. Session construction consumes that Plan rather than rediscovering settings or resources, re-verifies every snapshotted resource, and rejects any identity, capability, model, prompt-input, or tool-surface mismatch. Grant revocation can narrow the live set, but a later grant cannot expand an active Plan. Stable excludes every user/project/managed executable Extension path and loads only LA-owned inline runtime factories.
- External Extension approvals create a read-only, content-addressed v2 staged tree. Extension Host protocol v1 re-verifies and privately restages the exact approved bytes, then runs the Extension in a separate `srt` child with Node permissions, sanitized environment, zero direct grants, authenticated JSONL, timeout/crash isolation, and a pure-tool-only Pi compatibility adapter. General and isolated CAT constructors reject external paths rather than loading them in the Agent process. Legacy path/digest approvals cannot authorize staged execution; unsupported event/command/UI/render surfaces fail closed; Stable still excludes every external executable Extension until a later explicit activation Gate.
- Stable Package Center now routes only signed declarative `.lapkg` Preview and v2 activation. The old npm install/preview endpoints return `410`, the npm catalog is discovery-only, and General Runs resolve managed resources only from the frozen v2 registry; legacy `installed-v1` is exposed only as a path-redacted read-only inventory and is never loaded or rewritten. The strict archive verifier bounds paths and sizes and rejects executable/archive/package-manager surfaces; Ed25519 verification covers the complete canonical manifest/resource projection against explicitly injected publisher roots. Preview performs no fetch, subprocess, extraction, persistence or activation and binds the complete source, signer, resource and risk plan. Activation revalidates the exact bytes and approval, stages on the same root, verifies extracted resources, publishes read-only content plus an fsync-backed atomic registry under one writer lock, and never exposes Extensions. Before routes, the process acquires a fail-closed v2 Package-root lease (a narrow precursor, not a substitute for LA-021's full dataRoot lease), then recovery only proves exact rollback/finalization; ambiguity persists a blocking marker. No production publisher key is embedded or inferred, so a build with zero approved roots visibly keeps new activation disabled instead of weakening signature trust.
- LA-owned settings, notification/team-role configuration, project agent settings, standalone file grants, Pi trust decisions, and staged Extension trust now have a startup-only SQLite authority seam after strict source validation, exact raw-byte backup, source/payload digests, revision/CAS parity, and an authority marker. Once installed, these readers/writers do not fall back to their legacy JSON files. Provider secrets remain Keychain/reference-only and Pi native `settings.json` remains owned by Pi's SettingsManager; neither is imported into LA SQLite. This is synthetic-only evidence: no real `data/**` or real `~/.pi/agent/trust.json` was read or migrated in the campaign.
- A strict v1 Run Worker bootstrap/JSONL protocol and Supervisor lifecycle own every newly started standalone General root Run, Project CAT root Run, Private Eval single generation, and Team specialist transport Session. General and CAT/Eval/Team preparation use versioned bidirectional RPC carried inside that single Supervisor channel. Each Worker accepts only its strict frozen Plan, returns hashes for the exact prompt/tools/resources/grants it prepared, and cannot prompt before Host activation. Task-backed General, Project CAT, and Team Runs durably record the matching `ExecutionSnapshot` before activation. Private Eval has no canonical Task locator, so the Host validates its attestation in memory before activation and its existing Eval execution manifest remains the durable domain truth after completion. Team validates the signed child scope against exact Project/Workflow/Role identity before launch, attests only its read-only evidence-tool subset, and keeps Stable executable Package Extensions blocked. Permission, delegation, typed Extension UI, Host-owned CAT tools, and canonical Task writes remain Host decisions; server-tool cancellation propagates across RPC; active registry state exposes exact worker/epoch identity; Stop and crash flow through the canonical owner. Existing active Runs are never hot-migrated. Standalone compaction/fork, read-only delegated children, and non-Run CAT prompt/catalog/compaction support operations now use the same Worker authorities without a Host Agent-session fallback; child Worker identity and epoch are canonical Activity, while support operations retain their existing durable domain result because they are not Task Runs. The dormant Maintainer migration Agent remains Stable-disabled and is separately owned by LA-050; this cutover does not claim an Extension Host or OS-level sandbox boundary.
- Each General Run records Pi version, working directory, file-grant IDs, Packages, active tools, resource hashes, request shape, and resource conflicts. Winner/shadowed conflicts become typed Activity.
- Standalone filesystem authority is the private Chat workspace plus active canonical file grants. Every production tool must resolve by exact name to LA's schema-v1 structured capability inventory before a General, CAT, or Maintainer session can expose it; unknown tools and aliases are blocked rather than classified by name or treated as a generic bridge. Every generic read/list/search/write path in General, CAT, and managed document tools is then authorized by the single `FileCapabilityBroker` against current realpath grants. General re-resolves active grants on every tool call so revocation takes effect immediately; CAT generic tools receive read/list/search authority only for the current Project roots, while CAT-native writes remain behind their existing proposal/evidence/QA/delivery gates. Generic writes, network, shell, bridge, and executable-code decisions retain their permission gates.
- Network, process, and Secret authority are separate from filesystem and permission decisions. Public-web calls are normalized to an exact scheme/host/port grant and reject credential-bearing URLs plus private/loopback targets by default; bridge tools without an exact Run grant are blocked. Bash must pass the exact `sandboxed-shell` process template both at the runtime hook and immediately before the managed sandbox spawn. Web-provider credentials resolve only after a consumer/opaque-secret handle is authorized; handles never contain the value, and plaintext stored Pi credential values are rejected rather than returned to a tool. Pi provider transport remains runtime-internal, Package preview remains inert, and managed document tools remain local-only unless a future explicit capability says otherwise.
- Composer file attachments are explicit next-Run selections, not ambient disk access. PNG/JPEG/WebP grants become Pi native `prompt(images)` input only when the resolved model reports image capability; non-image attachments stay in the authorized tool/OCR path, and active Runs cannot expand their frozen resource set.
- Standalone and Project Main transport use the same Pi-native steer/follow-up/Stop/compaction path. A server-owned durable queue beside the Task snapshot gives Pi follow-ups stable identities for pause/resume, edit/delete/reorder, retry, and recovery after interruption; renderer state is not queue truth. Server-owned delegation uses verified `pi-subagents` for zero-Package Runs and Pi RPC v1 for selected Team Package resources; direct Package `subagent`/`wait` activation is blocked.
- The active provider/model pair is an atomic, Mac-local user preference. General Run resolution uses that complete global pair before the bundled project fallback; Composer and Settings read the same resolved `providers.defaults`, and sending a message does not reset it. A currently running Run remains immutable.
- Pending tool/resource permissions are server-owned Task/Run/session-scoped requests rendered by the shared `PermissionRequestSurface` in the current Composer. It is a plain surface without a blocking `<dialog>` or global backdrop; tool actions support once/conversation/always/deny, while resource trust requires the exact trust-summary action. The renderer accepts stream events and polls the canonical pending endpoint while a Run is alive so a reconnect cannot turn a request into a silent timeout. Switching Tasks hides the surface without deciding it; stopping the Task cancels that session's pending requests.
- Personal and Project Library use lexical retrieval and an exact managed multilingual-E5 pack for optional vector/hybrid retrieval. Confirmed Memory supports explicit personal/client/franchise/project/locale scope, expiry, explicit conflict groups and user supersede/revoke history. The Host creates the only immutable per-Run lexical/local-semantic snapshot; Workers never enumerate live Memory, a missing pack is visibly lexical-only, and Memory remains recall-only rather than CAT evidence or Project Truth.
- Managed document packs are exact, offline-capable, provenance-recorded capabilities. PaddleOCR and Office passed the recorded local qualification. Their outputs can carry a schema-v1 declarative Rich Artifact with markdown, table, chart, image, page-overlay, diff, and file-reference blocks; Electron previews the model without active content and exports inert HTML/PDF/PNG only through an explicit native save decision. MinerU remains `unqualified` and cannot fall back to a system command or cloud service.
- Package Center separates read-only community discovery from signed `.lapkg` Preview, explicit risk approval, atomic v2 activation and future-Run resource freezing. Opening the catalog never installs or runs Package code.
- Stable blocks every Maintainer mutation and does not mount its renderer panel. Existing maintenance artifacts remain readable through canonical Task history while the isolated candidate implementation awaits migration to developer/CI tooling.
- The eight Agent personas remain Conversation identities, and Auden remains one Lead Linguist persona serving the setup and final phase contracts.
- Task Main Stop dispatches Stable Single/General through the active registry and Team through workflow Stop. Private Eval execution/Stop is hidden and blocked in Stable; its retained implementation and durable history are reserved for later migration to CI tooling.
- Pi `0.80.10` is exact-pinned. The server shares one injected `ModelRuntime`; persistent credentials remain atomic and resolve only official environment references or LA-owned Keychain commands.
- Electron Settings exposes direct OAuth/API-key connection actions beside the current model, plus explicit managed-runtime restart/repair and preview-plus-plan-hash cache cleanup. None of those actions reads or deletes durable Task/Project data through the renderer.
