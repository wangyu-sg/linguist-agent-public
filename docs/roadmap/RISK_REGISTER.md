## 1. 评分规则

- **P0**：继续开放相关能力或扩大并发/分发前必须封住。
- **P1**：会破坏数据、信任边界、恢复或发布可信度，应在核心迁移前解决。
- **P2**：维护、性能或治理风险，可按依赖排期。
- “已确认”表示代码调用链直接成立；“高置信”表示缺动态时序/恶意 PoC；“未知”表示没有足够代码或运行证据。

## 3. 首批动态验证计划

| 验证 | 方法 | 不写生产数据 | 成功条件 |
|---|---|---|---|
| Sandbox interleaving | fake/barrier 包住真实 manager，两个互斥 roots 随机调度 | 使用临时目录 | 每个 prepared/spawned command 的 config hash 恒等于其 Run |
| Prompt fail-closed | 让 mandatory+tools+history 分别溢出 | 纯 fixture | 任何溢出都不能产生可启动 `ready` |
| Permission invalid input | 从 HTTP patch 到 session tool decision | temp runtime root | unknown/missing/非法类型稳定拒绝且不写宽松配置 |
| Package preview inert | instrument `child_process`、fetch、fs roots | fake package/临时 quarantine | 目标 archive 获取后零额外网络、零 subprocess |
| Extension host access | 恶意扩展尝试 fs/env/process/net | 临时 host | Stable 直接拒绝；隔离阶段全部 capability denied |
| Storage concurrency | 两进程争用同 dataRoot | synthetic runtime root | 只有 lease holder 能写；另一进程写前失败 |
